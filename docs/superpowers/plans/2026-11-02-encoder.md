# giffy encoder plan

Goal: wiggle GIFs at the originals' full size, quality at least tuned Pillow's,
faster and no bigger. Target brain: 4-core ARM (Pi Zero 2 W / Pi 5). Drop-in for
shimmy's `make_gif(paths, out, width, delay_ms)`.

Baseline (M2 Pro, 4x 2592x1944 JPEG, 4 threads): tuned Pillow 460 ms synthetic,
366 ms real; ~70% is Pillow's single-threaded GIF write of all 6 playback frames.

## Design

Pillow keeps the JPEG decode and resize (libjpeg-turbo, releases the GIL). One C
file (`src/giffy/_giffy.c`) does the rest, releasing the GIL so Python threads
run it in parallel:

1. `palette(frames, w, h, k)`: one shared palette for all frames. Exact colours
   when the shot has <= k of them (lossless), else Wu's variance-split on a
   5-bit histogram of a ~1M-pixel sample, then k-means refinement on the bins.
2. `remap(rgb, w, h, palette, lut, mode)`: serpentine Floyd-Steinberg (or plain
   nearest / exact) with a shared lazily-filled 6-bit nearest-colour table. Fill
   value depends only on the bin, so output is identical for any thread count.
3. `lzw(indices, min_code_size)`: GIF LZW with a generation-tagged hash table
   (no clearing cost on table resets), written straight into 255-byte sub-blocks.

Python (`src/giffy/__init__.py`) loads frames in parallel (EXIF orientation,
optional resize with JPEG draft decode), builds the palette, maps and encodes
each *unique* frame once in parallel, and writes every playback frame from those
bytes with one global colour table.

## Tasks

1. C core + Python pipeline + CLI.
2. Tests: LZW round trip vs Pillow (and ffmpeg when present) across sizes, min
   code sizes and table resets; exact palettes are lossless; EXIF rotation;
   resize; determinism across thread counts; size mismatch error; drop-in API.
3. Benchmark (`bench/bench.py`): tuned Pillow vs giffy at full size, 1080, 320;
   time, file size, PSNR and blurred PSNR, synthetic scene + optional photos.
4. Tune from numbers (k-means iterations, dither choices). Keep only what wins.
5. Linux check (Docker on the ZimaBoard): builds with gcc, tests pass.
6. README with results; merge.

## Outcome (2026-11-02)

All tasks done. Changes from the plan, each decided by measurement:

- Dither and LZW fused into one raster-order pass so lossy LZW can see the
  LZW state; serpentine remap dropped (same quality, more code).
- Lossy LZW (default 4) + dither strength 14/16: beats tuned Pillow on size and
  both quality measures at full size on all 5 test shots.
- One k-means pass (passes 2-3 added <= 0.16 dB for a third of the time).
- Tried and dropped: two-band interleaving for ILP (<=15% on M2, needs bit-level
  joins), more lossy candidates (no change), full pass-through of lossy error
  (worse at equal size), capped child walks (walks average ~2 hops).
- Not measured: the Pi's ARM cores.
