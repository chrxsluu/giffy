# Alignment and even lighting: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** giffy lines the photos up on one point (the centre by default, or a tapped point), crops them to their shared 4:3 area, and evens out each lens's brightness and colour before encoding.

**Architecture:** One new C function in `_giffy.c` does the patch matching (zero-mean normalised cross-correlation). Every decision (detail, repeats, nearest detail, all-or-nothing, fill-in) is made in a new `align.py` on a fixed 320 px wide luma copy, so the answer doesn't depend on output size. The shift is then refined at the decoded resolution. A new `even.py` measures per-lens, per-channel gains on the aligned copy. `encode_shot()` in `__init__.py` runs the pipeline and returns the GIF together with the `Alignment` it used. Passing that `Alignment` back in skips the decisions, so the preview and the full GIF hold the same point.

**Tech Stack:** Python ≥ 3.11, Pillow ≥ 9.4, C11 extension (setuptools), pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-02-align-design.md`

## Global Constraints

- No new dependencies (no numpy, no OpenCV); Pillow does decode, resize, crop and per-channel LUTs.
- Slide only: no rotation, scale or warping.
- Crop to the shared area, keeping the photos' proportions: the largest rectangle of the frame's aspect ratio inside the shared area, centred in it.
- All or nothing: every frame aligned, or none.
- Nearest detail: within 15% of the frame width of the point; past that, unaligned.
- Evening: lens differences only; correction capped; a depth-free shot ends within 1% per channel per frame.
- `width` is the finished GIF's width after cropping.
- Alignment and evening are on by default; `align=None, even=False` gives byte-for-byte today's output.
- Alignment plus evening add under 20 ms per shot on the M2 Pro at any size.
- Output stays deterministic and identical for any thread count.
- `make_gif(paths, out, width, delay_ms)` stays a drop-in and still returns a `Path`.

## Review Focus

1. A point near the frame edge (a tap in a corner): the patch is clamped inside the frame and matching still works or falls back cleanly; nothing crashes. (Task 2)
2. A point given on a non-reference frame (a tap while lens 4 was showing): the still point ends up on what was tapped in that frame. (Task 2)
3. Tiny frames (smaller than one patch, e.g. 40×30) or a single photo: no crash, `status == "none"`, output as without alignment. (Tasks 2, 4)
4. A far subject with zero shift: no crop at all, output keeps its full size. (Task 4)
5. Reusing an `Alignment` with a different number of frames, a different reference, or a different aspect ratio raises `ValueError` instead of producing a skewed GIF. (Task 4)

## Constants (pinned; Task 5 may retune the thresholds, and must update the tests with them)

In `src/giffy/align.py`:

```python
ANALYSIS_W = 320      # decisions are made on a luma copy this wide (or the frame's width, if smaller)
PATCH = 0.10          # patch side, fraction of analysis width (32 px)
SEARCH_X = 0.12       # sideways search, fraction of width, each way, per lens step from the reference
SEARCH_Y = 0.03       # up-down search, fraction of height, each way
NCC_MIN = 0.60        # a match is good if its score is at least this...
UNIQUE_MIN = 0.08     # ...and beats the best score elsewhere (> PATCH/4 away) by at least this
DETAIL_MIN = 5.0      # luma standard deviation a patch needs to count as detailed
REPEAT_MAX = 0.90     # a patch whose self-match has a second peak this high is a repeating pattern
NEAREST_MAX = 0.15    # nearest-detail search radius, fraction of width
```

In `src/giffy/even.py`:

```python
GAIN_MIN, GAIN_MAX = 0.85, 1.18   # cap per channel
MID_LO, MID_HI = 16, 240          # only unclipped mid-tones are measured
EVEN_W = 80                       # gains are measured on copies this wide
```

**Interfaces:**
- Produces: `_giffy.match(ref: bytes, other: bytes, w: int, h: int, x: int, y: int, size: int, dx0: int, dy0: int, rx: int, ry: int) -> tuple[int, int, float, float]`. `ref` and `other` are 8-bit luma (`"L"` mode bytes), both `w*h`. The patch is the `size×size` square with top-left `(x, y)` in `ref`, and must lie inside `ref`. The function searches offsets `dx ∈ [dx0-rx, dx0+rx]`, `dy ∈ [dy0-ry, dy0+ry]`, skipping offsets where the patch would leave `other`, and returns `(dx, dy, best, second)`: the offset with the highest zero-mean NCC (ties: smallest `dy`, then smallest `dx`), the score, and the highest score at any offset more than `max(2, size // 4)` px (Chebyshev) from the best. With no valid offset it returns `(dx0, dy0, -1.0, -1.0)`. A flat patch (zero variance) scores 0 everywhere. The GIL is released while searching.

### Task 2: Alignment decisions, refinement and crop

**Files:**
- Create: `src/giffy/align.py`
- Test: `tests/test_align.py`

**Interfaces:**
- Consumes: `_giffy.match` (Task 1).
- Produces:

```python
@dataclass(frozen=True)
class Alignment:
    ref: int                                  # reference frame: (n - 1) // 2
    point: tuple[float, float]                # still point in the ref frame, fractions (after any move to nearby detail)
    shifts: tuple[tuple[float, float], ...]   # per frame: where the point sits minus where it sits in ref, fractions of w and h; ref is (0, 0)
    crop: tuple[float, float, float, float]   # left, top, right, bottom in ref-frame fractions; (0, 0, 1, 1) = no crop
    aspect: float                             # w / h of the frames it was made for
    status: str                               # "aligned" | "moved" (nearby detail used) | "none"
    confidence: float                         # worst frame's best score; 0.0 when status is "none"
    gains: tuple[tuple[float, float, float], ...] = ()   # filled by Task 3; () = no evening

CENTER = (0.5, 0.5)

def find(frames: list[Image.Image], at: tuple[float, float] | tuple[float, float, int] = CENTER) -> Alignment
def refine(frames: list[Image.Image], al: Alignment) -> list[tuple[int, int]]   # integer px shifts at these frames' size
def crop_boxes(size: tuple[int, int], shifts_px: list[tuple[int, int]]) -> list[tuple[int, int, int, int]]
```

`frames` are upright RGB images, all the same size, at any resolution. `find` makes every decision on `ANALYSIS_W` luma copies (`frame.convert("L")` resized with `Image.Resampling.BOX` to `ANALYSIS_W` wide, or left as is if the frame is narrower). `refine` re-runs `match` at the frames' own resolution in a window of ±(scale + 1) px around the analysis answer scaled up (patch side `PATCH` × width, capped at 128 px), and makes no decisions. `crop_boxes` returns one PIL box per frame. These are the largest rectangle with the frames' aspect ratio inside their shared area, centred in it and shifted per frame, so that every box has the same size.

**`find` decides, in this order:**

1. With fewer than 2 frames, or an analysis copy smaller than `2 × PATCH` in either side, return `status="none"`.
2. If `at` names a frame other than `ref`, match a patch around that point in that frame against `ref` (search ±`SEARCH_X × |frame − ref|` sideways, ±`SEARCH_Y` up-down). This gives the point in `ref` coordinates. A bad match (see 4) means `"none"`.
3. **Plain or repeating?** The patch around the point is plain if its luma standard deviation is below `DETAIL_MIN`. It is repeating if matching it against `ref` itself gives `second > REPEAT_MAX`. Either way, try candidate points on rings around it, spaced `PATCH/2` apart, out to `NEAREST_MAX × width`, nearest ring first and clockwise from the top within a ring. Take the first candidate that is neither plain nor repeating; status becomes `"moved"`. If none qualifies, the result is `"none"`.
4. **Match every other frame** against `ref`. Search ±`SEARCH_X × |i − ref|` sideways around 0 and ±`SEARCH_Y` up-down. A frame is good if `best ≥ NCC_MIN` and `best − second ≥ UNIQUE_MIN`.
5. **All or nothing.** If all frames are good, use their shifts. If exactly one frame is bad and there are at least 3 frames, fit `shift = step × (i − ref)` per axis by least squares to the good frames. If every good frame lies within `max(2 px, 0.25 × |step|)` of that fit, the bad frame takes the fitted shift. Otherwise, or if more than one frame is bad, return `"none"`.
6. Patches are clamped inside the frame, so a point near the edge uses the nearest in-frame patch.

### Task 3: Even lighting

**Files:**
- Create: `src/giffy/even.py`
- Test: `tests/test_align.py`

**Interfaces:**
- Consumes: `Alignment`, `crop_boxes` (Task 2).
- Produces:

```python
def gains(frames: list[Image.Image]) -> tuple[tuple[float, float, float], ...]   # frames already aligned + cropped
def apply(frame: Image.Image, g: tuple[float, float, float]) -> Image.Image       # per-channel LUT via Image.point
```

`gains` resizes each frame to `EVEN_W` wide (BOX) and builds the per-pixel mean of all frames. Per frame and channel, it takes the median of `frame / mean` over pixels where every frame is within `[MID_LO, MID_HI]` (no pixels: gain 1.0). It normalises so the product of the gains across frames is 1 per channel (the overall look doesn't move), then clamps to `[GAIN_MIN, GAIN_MAX]`. `apply` maps `v → min(255, round(v × g))` per channel and returns the frame unchanged when `g == (1, 1, 1)`.

```python
class Shot:

```

**Pipeline when `align` is not None (or `even` is True):**
1. Load the upright full-quality frame. JPEG draft decode targets `width / 0.85` (so up to a 15% crop still needs no upscaling), with no resize yet.
2. Get the `Alignment`, either `find(frames, at)` or the one passed in. A passed-in one must have the same frame count (`len(shifts) == len(frames)`), the same `ref`, and an `aspect` within 1% of these frames'. Otherwise raise `ValueError("alignment was made for a different shot")`.
3. `refine` it, compute `crop_boxes`, then crop. Then compute `gains` (or reuse `alignment.gains` if passed in non-empty) and `apply` them. Then resize to `width` (LANCZOS) if set. Then `tobytes` and encode as today.
4. The returned `Alignment` carries the gains, so passing it to the full-size call reproduces both the crop and the lighting.

When `align is None and even is False`, run the code exactly as it is today (the current `_load`). Pass `align=None` with `even=True` to even the frames without shifting them. The CLI gains `--no-align`, `--align-at X Y [FRAME]` and `--no-even`.
